# 2026-08-28: Keycard Activate guide — "Resume Step-by-Step Guide" button

Second pass on the [Keycard "Activate" step-by-step guide](../keycard-activate-guide.md) (built earlier the same day). `public/index.html` only — the entry template inside `j()` plus the guide's own `<script>` block at the end of the file. Nothing in `functions/`, `src/app.js`, Firestore, or any Keycard validation/submit path was touched.

Ask: staff who dismiss the walkthrough need a way to bring it back **where they left off**, not from step 1, without losing anything they'd already typed.

- **Button:** `.era-k-resume-guide-btn`, rendered inside each Keycard entry's `.era-k-action-wrap` directly under the Action select, `era-field-hidden` by default. Shown only while that entry is in guide mode *and* still set to Activate; "Manually (I am a professional)" or switching to another action hides it again.
- **Per-entry state:** a `WeakMap` keyed by the real `.era-entry-block` holding `{mode, step, completed}`. Keyed by the element so it dies with the entry (no cleanup path to get wrong) and so two entries each keep their own resume point.
- **Park vs. finish:** `eraGuideEnd()` now takes a `completed` flag. Terminal Send/Edit/Cancel/Save click and advancing past the last step pass `true` (resume point resets, button relabels to "Restart Step-by-Step Guide"); ✕, a vanished tracked element, and switching to another entry's guide pass `false`, which saves the current `stepIndex`.
- **Where it resumes** (`resolveResumeIndex`): from the saved step, skip forward over anything the real form now reports as done (required steps reuse their existing `satisfied()`; the click-only "Save or Wait" step got a `resumeDone()` keyed off its button row having hidden itself — which is exactly what both real buttons already do when clicked), then, if that step's target is no longer on the page (the Preview modal having been closed is the real case), walk back to the nearest earlier step whose target *is* visible and re-run the forward skip. Optional "click outside" steps are never auto-skipped — they have no readable done-state, and re-showing one costs a single click.
- **No adverse effect when already visible:** clicking Resume while the guide is up on that same entry returns early, and the optional-step outside-click handler now explicitly ignores clicks on this button so it can't quietly advance a step.
- Still never writes into the form: like the rest of the guide it only reads real fields' own state, so form data, selections, and validation are all untouched.
- Verified with `node --check` on the extracted guide `<script>` block plus a rebuilt throwaway browser harness (served over `http://localhost` — a `file://` page renders as a static snapshot in the Browser pane and can't be driven), and spot-checked against the real `public/index.html` served locally. Full coverage list in [the feature doc's Testing section](../keycard-activate-guide.md#testing).
