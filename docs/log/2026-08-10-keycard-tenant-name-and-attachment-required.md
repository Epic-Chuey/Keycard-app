# 2026-08-10 — CW Email Request, Keycard tab: drop First/Last Name, repurpose Tenant Name, require an attachment before send

Scoped to `emailRequestAttachmentsEmbed`'s Keycard mode only, after a real user test came back broken. Removed the separate "First Name"/"Last Name" fields (`era-k-first`/`era-k-last`) from each Keycard entry template; the existing "Tenant Name" field (`era-k-tenantName`) was relabeled "Tenant First/Last Name" and made required, becoming the sole per-entry name field instead of three overlapping ones. `eraCollectFields()` dropped `first`/`last` from the entry payload.

Added a required-attachment check on both sides: client-side, `eraSubmitForm()` now blocks submission with an inline error if Keycard mode has no pending files, before any `fetch()` call; server-side, `Code.js`'s `buildKeycard()` now also rejects a missing/empty `p.attachments` before other validation, since `doPost()` is a public endpoint that direct calls could otherwise bypass — previously this was only a UI note with no real enforcement. `requiredBase` in `Code.js` changed from `["companyName", "first", "last", "keycard"]` to `["companyName", "tenantName", "keycard"]`; the per-entry email body line now relies solely on `eraCompanyDisplay(entry)` (`"CompanyName / TenantName"`) instead of a separate `first + last` concatenation.

The real handler is `Google Script/email-request-attachments/Code.js` (outside this repo) — needs its own `clasp push` + Apps Script "New version" deploy alongside `firebase deploy --only hosting`. Separately, Huy's test also hit "Send failed: Gmail operation not allowed" — a Gmail/Workspace-side send failure inside `GmailApp.sendEmail()` itself, unrelated to this session's validation changes and not diagnosable without Apps Script Executions/Admin console access.

Same-day addendum: the separate standalone Apps Script page (`Google Script/email-request-attachments/index.html`, its own `doGet()` UI, previously untouched) had its Keycard tab's "Company / Tenant Name" renamed to "Tenant Company Name" and First/Last Name combined into one "Tenant First and Last Name" field (`k_companyName`/`k_tenantName`) — this incidentally fixed a real pre-existing bug where that page's `collectFields()` still sent the old flat `company`/`first`/`last` names, which no longer matched `buildKeycard()`'s field requirements and would have failed server-side validation. A second addendum then unified wording: the embed tab's labels were changed to match this page's ("Tenant Company Name"/"Tenant First and Last Name") — label-only, field keys unchanged.

Files: `public/index.html` (embedded `<script>`), `Google Script/email-request-attachments/Code.js`, `Google Script/email-request-attachments/index.html`
