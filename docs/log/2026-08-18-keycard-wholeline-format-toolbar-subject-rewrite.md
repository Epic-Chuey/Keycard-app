# 2026-08-18: Keycard: whole-line highlight, Format toolbar, subject rewrite (fourth pass)

Four changes to CW Email Request > Keycard. (1) The bold+green Cubework highlight (third pass, word-only) now wraps the *entire* header line — company/keycard#/action or the Request Card line, fee suffix included — via a new `LINE_WRAP_START`/`LINE_WRAP_END` sentinel pair swapped for a styled `<span>` (or stripped for Unis) after escaping; `buildEntryLine()` now takes a `wrapHeaderForHtml` boolean instead of a `servesText` string. (2) When Email and/or Phone is entered, a blank line now separates the header line from the Email/Phone block (Access stays grouped with the header). (3) The subject line was rewritten from one shared template to five: Activate/De-Activate/Troubleshoot/Transfer → `"{Location} - Keycard {Action} - {First Company Name}"`, Request Card → `"{Location} - Card Requested ({Keycard Quantity})"` (the existing HikCentral-bypass blank-company fallback is preserved).

(4) The Preview modal gained a **Format toolbar** (`#era_previewFormatBtn`/`#era_previewToolbar` — Bold/Italic/Underline, Font Family, Font Size, text color) that makes `#era_previewBody` `contentEditable` via `document.execCommand`, kept separate from the existing "Edit" button (unchanged — still just closes the modal). Whatever is in the preview body at Submit time (edited or not) is captured into a new opt-in `htmlBodyOverride` field on `submitEmailRequest()`'s payload, which — only when present — replaces the freshly-built `htmlBody` verbatim right before the Graph send, so a hand-edited preview and the actually-sent email match exactly; an unedited submission is byte-for-byte unchanged from before this pass. The Outlook-deeplink fallback (plain-text only, per pitfall #7) can't carry the override — irrelevant today since `ERA_SUBMIT_MODE` is `"graph"`.
