# 2026-08-16 (eighth pass) — CW Email Request, Printer tab: Tenant + Troubleshoot minimal view, Paid Wi-Fi, required attachment

Ticking "Tenant" now hides and force-unchecks "Setup New Printer"/"New/Replace Printer Request" (Cubework-only checkboxes). When both "Tenant" and "Troubleshoot" are ticked, the entry shows only Office or Warehouse, Company Name, Tenant Name, Unit Number, Printer Model, and Phone (Email and the shared "Describe the issue" box both hide, confirmed via clarification); a new per-entry "Paid Wi-Fi" checkbox appears only in this combo when that entry's Office or Warehouse is set to "Warehouse". This combo now requires an attachment (Printer's only attachment-required case — Cubework+Troubleshoot and plain Troubleshoot stay optional), enforced both client-side (`eraSubmitForm()` pre-check) and server-side. `eraApplyPrinterCubeworkVisibility()` was renamed to `eraApplyPrinterVisibility()` (now covers this non-Cubework case too) and gained `isTenantTroubleshoot` (only recognized when Cubework isn't also ticked). Server-side, `buildGeneric()` added a required-fields branch for `isTenantTroubleshoot` (companyName, unit, extra, phone — Email excluded, Tenant Name never required), excluded it from the Troubleshoot relaxation and from the shared "Describe the issue" check, added the attachment-required check, and prints `Paid Wi-Fi: Yes` when set.
