# 2026-08-21: Per-card Signature/ID — Date fields, Notes reorder, auto E-Signature, remote-sync ink

Follow-up to the same day's per-card Signature/ID feature (`.era-k-signid-wrap`, see the "Per-card Signature / ID" section of [email-request-attachments-embed-tab.md](../email-request-attachments-embed-tab.md)). All changes are inside `public/index.html`'s CW Email Request embed script/markup plus three `functions/index.js` additions — no `src/app.js` change needed (this tab's classic `<script>` doesn't go through the `npm run build` pipeline).

**Card layout (markup only):**
- Added **Date Issued** / **Date Returned** (`.era-k-dateIssued`/`.era-k-dateReturned`, plain `<input type="date">`, no validation) directly above the "Signature / ID" label — always visible alongside that section, same as Signature/ID itself (not hidden for Troubleshoot/Transfer/etc.). Threaded through `eraBuildKeycardEntryDataForHistory`/`eraFillKeycardEntry` so Save/Edit round-trips them like every other entry field.
- Moved the **Notes / anything else to flag** textarea (`.era-k-notes`) from just above the Fee row down into `.era-k-signid-wrap`, now sitting right after the Photo ID status line and before the "what next" decision panel. Its `era-field-hidden` toggle in `i()` still matches by class, so Troubleshoot/Replacement hiding it is unaffected by the DOM move.
- Renamed the "Send for tenant e-signature instead" checkbox label to **"E-Signature"** (class/behavior unchanged).

**Auto-fire e-signature:** checking "E-Signature" now auto-fills the Tenant E-Signature Email from this entry's own Tenant Email field (only if the e-sig field is still empty) and, if an email is present, clicks Send immediately — staff no longer have to retype the address or click Send by hand when Tenant Email was already filled in. Status wording changed to match the ask: `sendStatus` reads "Sent to `<email>` — waiting signature." and `photoStatus` is set to "Waiting for photo id." at the same moment.

**Hid "Do you have the physical keycard form?"** (`#era_k_haveFormCard`): dropped the `era-k-attach-fields` class so `K()` no longer un-hides it — it now stays permanently `era-field-hidden`. Side effect (accepted, not separately gated): since its Yes/No radios can never be checked anymore, `eraKeycardHaveFormValue()` always returns `""`, so the old "Open Keycard Form" (`#era_k_formSection`, the PDF-fill modal flow) also never shows — consistent with the new inline per-card Signature/ID replacing that path.

**Remote signature now syncs back automatically (backend + client):** previously, once a tenant completed the remote link, staff saw a "Download & Attach" button that only attached the final flattened PDF — the local canvas stayed blank and Photo ID showed no visual confirmation. Now, the moment `pollRemote()` sees `status:"completed"`, `finishRemoteSignature()` runs on its own (button removed from the normal path, kept only as an error-recovery fallback):
- Attaches the signed PDF exactly as before.
- **Inks the actual customer signature onto the local `<canvas>`** — new: `submitSignatureRequest` (`functions/index.js`) now also saves the raw `signaturePngBase64` it already receives to Storage (`signatureRequests/{token}-signature.png`, path stored on the doc as `signaturePngPath`) instead of discarding it once the PDF is built; `getSignedKeycardFormPdf` reads it back and returns it as `signatureBase64` alongside the PDF. The client draws it into the canvas via `Image`/`drawImage` and sets `hasInk = true`.
- **Marks Photo ID satisfied** — same pattern: the tenant's submitted photo ID (`photoIdBase64`/`photoIdContentType`/`photoIdFileName` in the request body) is now always saved to Storage at `signatureRequests/{token}-photoid-<name>` (previously only saved when `historyRequestId` was set, for the *separate* Keycard Submission History photo-ID map) and its path/content-type/filename recorded on the completed doc (`photoIdAttachmentPath`/`photoIdContentType`/`photoIdFileName`). `getSignedKeycardFormPdf` reads it back too; the client attaches it to `g.keycard` and sets `photoStatus.innerHTML = "✅ See the attachment below."`.
- Both new Storage reads in `getSignedKeycardFormPdf` are best-effort (try/catch, `null` on failure) so an older completed request that predates these fields, or a transient Storage read error, still returns the PDF instead of failing the whole call.

**Not done / accepted limitations:**
- The auto-finish above only fires while the "Wait for Signature Now" polling loop (`remoteInterval`) is actually running in an open browser tab — it does not (yet) re-run on reopening a Saved/Pending submission later via History > Edit. A reasonable follow-up if staff routinely use "Save & Leave" instead of "Wait for Signature Now" for this new inline flow.
- Date Issued/Returned are not threaded into the sent email body (`functions/emailRequest.js`) — like the signature/Photo ID themselves, they're treated as paperwork captured alongside the card rather than body text; add a body line later if that's wanted.
