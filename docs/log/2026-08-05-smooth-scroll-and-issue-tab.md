# 2026-08-05: Smooth scrolling app-wide + Issue tab built

**Smooth scrolling.** Replaced the outer-page-only `html { scroll-behavior: smooth; }` in `index.html`/`email-request.html` with a universal `* { scroll-behavior: smooth; }` (wrapped in `@media (prefers-reduced-motion: no-preference)`), so nested scroll boxes (Roadmap card bodies, Compare modal columns, Export column picker, Markup canvas, gate modal) inherit it too. Affects keyboard scrolling and programmatic `scrollTo`/`scrollIntoView`; existing scroll-position-*restore* code (`scrollTop =` after a re-render) was left as instant assignment on purpose, to avoid an unwanted jump on every data refresh.

**Issue tab.** New eighth "app" (`ISSUE_APP_KEY = "issue"`), a manually-entered facilities/IT issue tracker split into two region tabs (Cali / Outside Cali, one `issueItems` collection with a `region` field) each with an Active/Pending/Complete filter — see [docs/issue-tab.md](../issue-tab.md). Deliberately reuses existing mechanics: Roadmap's selection-checkbox-for-export (not a "mark complete" box — status is a separate three-way select), Standup's fixed `STANDUP_TAGS` plus Issue's own runtime-growable `issueTagCatalog`, Roadmap's Excel+PDF+PNG export, and filter tabs with live `(N)` counts (a kanban board was offered and declined). New Firestore collections `issueItems`/`issueTagCatalog` (write-blocked for clients, callables only); `"issue"` added to `MANAGEABLE_TABS` in both `app.js` and `functions/index.js`.

Same-day follow-up fixed two bugs: `#issueRegionTabs`/`#issueStatusTabs` weren't docked under `#appSwitcher` like other tabs' nav rows (fixed by wrapping both in a sticky `#issueControlsRow`), and `#issueAddRow` ("New issue" form) had `display:none` with nothing ever toggling it back on — fixed by having `updateAppChrome()` show it when `isIssue && canEdit()`, mirroring Roadmap's own gating.

Files: `public/index.html`, `public/app.js`, `functions/index.js`, `firestore.rules`
