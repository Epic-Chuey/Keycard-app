# 2026-08-10: Standup/Daily To-Do/Issue tags unified into one shared catalog

Standup, Daily To-Do, and Issue each kept a separate runtime-growable custom-tag catalog (`standupTagCatalog`/`dailyTodoTagCatalog`/`issueTagCatalog`) on top of the shared fixed 8 (`STANDUP_TAGS`), so a custom tag created in one tab was invisible to the others — the Standup → Issue transfer dropped any non-fixed tag to blank, and the Daily To-Do → Standup bridge forced everything to `"other"`. Unified into one `sharedTagCatalog` collection with `addSharedTag`/`deleteSharedTag` callables (`functions/index.js`, case-insensitive label dedupe), one `firestore.rules` block, and one `allSharedCustomTags` cache/`subscribeToSharedTagCatalog()` listener in `app.js` (existing per-tab wrapper names like `standupAllTags()` kept as thin wrappers so other call sites didn't need to change); both bridges now carry `item.tag` over as-is. A one-time, owner-only `migrateTagCatalogsToShared` callable (dry-run capable, idempotent) folds the three old collections into the new one and rewrites `custom:<oldId>` references in `issueItems`/`standupSaves`/`dailyTodoSaves`; the old collections aren't deleted. A same-day follow-up added an owner-only migration UI (`#tagMigrationWrap` on the Access tab, Preview/Run buttons) since the migration hadn't been run yet and the New tab's tag select was still empty.

Files: `functions/index.js`, `firestore.rules`, `src/app.js`, `public/app.js`, `public/index.html`, `docs/tag-feature.md`
