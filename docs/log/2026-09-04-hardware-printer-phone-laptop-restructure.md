# 2026-09-04 — CW Email Request: Printer/Phone/Laptop folded into Hardware ▾

Per Huy's request, restructured the CW Email Request mode bar (`#era_tabs`): Printer, Phone, and Laptop no longer have their own top-level tab — they're reachable only through the Hardware ▾ dropdown now.

- **Hardware > Printer** — a direct selectable option. The "Printer" label itself is clickable (switches into Printer mode, no preset — same as the old standalone tab's label click), and hovering still cascades into the real Cubework/Tenant quick-picks (same items/attributes as the old Printer tab dropdown), each of which presets the same five checkboxes AND switches into Printer mode.
- **Hardware > Laptop/Phone > Phone** and **> Laptop** — two flat, real leaves alongside the pre-existing "New Hire" placeholder leaf. Selecting either switches straight into the real Phone/Laptop tab content.
- Nothing about the three modes' real field-form content, validation, checkboxes, or backend submit path changed — only the trigger UI (top-level tab + Printer's own dropdown) moved. The Printer-only thunderstorm hover effect still works (same `#era_pr_tabDropdown` id).
- `eraSwitchToModeTab(tabEl)` was split into a shared `eraActivateMode(mode, activeTabEl)` so the generic top-level tab click listener and the new Hardware-menu leaf clicks (which have no top-level tab of their own to read `data-mode` off of) share one implementation instead of duplicating it.
- **Access-control fix, found before deploy:** the `hardware` era-mode was deliberately stripped from every existing non-owner user on 2026-09-02 specifically so nobody gets it without an explicit admin grant — while Printer/Phone/Laptop's own mode grants were untouched. Gating the Hardware tab's visibility solely on `canSeeMode("hardware")` would have silently locked every already-granted Printer/Phone/Laptop user out of all three, with no way back short of an admin explicitly granting "Hardware" (which would also hand them AP/Node/Camera/NVR access nobody asked for). Fixed: the Hardware tab now also stays visible if the user can reach Printer, Phone, or Laptop (or any Hardware category) even without the "hardware" grant itself; each individual leaf still narrows further by its own pre-existing mode check, layered under the existing Hardware-category gate, never replacing it.

No `src/app.js`/`functions/index.js` changes were needed — `ERA_MODES` already included `printer`/`phone`/`laptop`/`hardware`, and `requireEraAccess()` already checks submits by mode string regardless of which UI reaches it. `node --check` passed on the embed script extracted from `public/index.html`.

See [docs/hardware-tab-hover-menu.md](../hardware-tab-hover-menu.md#printerphonelaptop-restructure-2026-09-04) for the full writeup.
