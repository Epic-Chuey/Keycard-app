# 2026-08-22: De-activate entry tweaks — Company Name on its row, Access Level hidden, removable Note

Per Huy's request, scoped to a Keycard entry set to **De-activate** only. `public/index.html` (CW Email Request embed markup/script) and `functions/emailRequest.js` (`buildKeycard()`).

- **Company Name shown, same line as Tenant First and Last Name/Keycard Number:** `.era-k-companyName` was previously permanently hidden and auto-mirrored from `.era-k-tenantName` on every keystroke (see [2026-08-21's Tenant Company Name hide](2026-08-21-signid-companyname-hide-submission-search.md)). It's now wrapped in `.era-k-companyName-wrap`, shown only when that entry's action is De-activate, on a new 3-column `era-row3` grid alongside Tenant Name/Keycard Number. The mirror-from-Tenant-Name listener now only fires while the wrap is hidden, so a typed De-activate Company Name survives further Tenant Name edits.
- **Access Level checkboxes hidden for De-activate:** label + Standard/WH Only/Office Only/Other checks + custom-text input now live together in `.era-k-accessLevel-wrap`, hidden by `i()` for De-activate. The checkboxes/value underneath are untouched (still defaults "Standard"), but `buildKeycard()` now skips the "Access: ..." line entirely for a `deactivate` entry so that unseen default doesn't show up in the email/Preview.
- **Red ✕ to remove the Note:** Notes textarea wrapped in `.era-k-notes-wrap`; a `.era-k-notes-removeBtn` shows once a De-activate entry's note has been opened (pairs with the existing "+ Add Note" toggle). Clears the text, resets `dataset.eraNoteOpened`, re-hides the box.
- **Server now actually prints the per-entry Company Name for De-activate:** the entry name line previously only ever used the mode-level, Activate-only "Licensee Company Name" field + Tenant Name — a De-activate entry's own `companyName` was collected (for required-field validation) but never printed. Now a `deactivate` entry's own `companyName` is used in that line instead; every other action is unchanged.
- Preview and Send both already go through the same `buildEmailRequest()` → `buildKeycard()` path (`buildEmailRequestPreview`/`submitEmailRequest`, `functions/index.js`), so all of the above shows up in the Preview modal with no separate change needed there.
- Verified via a throwaway Node script calling `buildEmailRequest()` with mock De-activate and Activate entries (Company Name printed / Access line absent for De-activate; Access line + licensee-name fallback unchanged for Activate) and `node --check` on the extracted embed `<script>` block (this file's giant single-line functions make a naive diff-review unreliable otherwise). Not click-tested in a real browser this pass.
