# 2026-08-18: CW Email Request — Keycard multiple locations, org-wide shared email-address history

Two additions to the CW Email Request tab, both scoped to `emailRequestAttachmentsEmbed` (`public/index.html`'s embed `<script>`, `functions/emailRequest.js`, `functions/index.js`, `src/app.js`, `firestore.rules`):

**Keycard: multiple locations.** The shared `#era_location` field (Location #1, used by every mode) gets a Keycard-only `+ Add location` button (`eraAddLocationRow()`/`eraRenumberLocationRows()`/`eraSyncLocationUiForMode()`) so a request that touches more than one place can list them all. Only visible on the Keycard tab (hidden, not cleared, on every other mode). Subject Logic is untouched — the subject still comes from Location #1 alone. `buildKeycard()` now accepts `extraLocationBodyLines`: when present, the location line becomes a `Location #1: …` / `Location #2: …` block, each directly below the previous, and the whole block renders bold + red in the sent email/Preview (unconditional, via a `LOC_START`/`LOC_END` sentinel pair — same technique as the existing Transfer From/To red block) to flag the multi-location request to whoever creates the keycard(s). Zero extra locations → byte-identical to the old single-line behavior.

**Shared email-address history, all six modes.** Every real email input (9 distinct field roles, from the top-level requester email down to each mode's manager/tenant/personal email fields) now offers up to 5 org-wide "recently used" suggestions — selectable, and individually removable via ✕ — shared across everyone who uses the tab, not per-browser (same shape as the existing shared Location/Tag catalogs). New Firestore collection `sharedEmailHistory/{fieldKey}` (`allow write: if false`, read gated on `tabAllowed("emailRequestAttachmentsEmbed")`), two new callables `addSharedEmailHistory`/`deleteSharedEmailHistory` (`requireRole(request,"view")`, matching `submitEmailRequest`'s own minimum), and a new `src/app.js` bridge (`window.getSharedEmailHistory()` + the two callables) for the same reason `window.submitCwEmailRequest` exists — the embed's classic `<script>` can't import the Firestore SDK. The suggestion panel itself is a single floating `.era-email-suggest-panel`, positioned via `getBoundingClientRect()` rather than CSS, to sidestep this app's usual ancestor-positioning fragility.

Files: `public/index.html`, `src/app.js` (+ rebuilt `public/app.js`), `functions/emailRequest.js`, `functions/index.js`, `firestore.rules`.
