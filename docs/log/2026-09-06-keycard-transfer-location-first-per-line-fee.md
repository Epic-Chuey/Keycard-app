# 2026-09-06 — CW Email Request, Keycard > Transfer: Location-first layout, per-line Fee/X, single Add Keycard button

Per Huy's request, a refinement pass on the same-day Transfer restructuring (repeating Location pairs / Keycard groups via `addTransferLocPair()`/`addTransferKcGroup()`, `era_k_locationGroup` hiding the shared Location field when every entry is Transfer).

## What changed

1. **Preview no longer requires Location** when every current keycard entry is set to Transfer. `Le()` (the shared Preview/Send validation) used to require `#era_location` unconditionally, even though `era_k_locationGroup` already hides that field in this exact case — so Preview could be blocked on a field the user could no longer see. Fixed by factoring the "every entry is Transfer" check into a shared `eraKeycardAllTransfer()` and having `Le()` skip the Location requirement only when that's true (every other mode/action, and any mixed-action Keycard request, is unaffected).
2. **All Transfer From/To location pairs now render above all keycard (Company/Tenant/Keycard#) lines**, each From/To pair still grouped together, additional pairs still stacking underneath the previous one. Line 1's Company Name/Tenant Name/Keycard Number (shared markup every other action also uses) and its Fee checkbox are physically moved into/out of the Transfer row on every action change (`eraSyncTransferLine1Position()`, via two fixed anchor placeholders) rather than duplicated.
3. **Every keycard line now has its own Fee checkbox and ✕ remove button.** Line 1 reuses the existing `.era-k-fee` checkbox as-is (same behavior, just repositioned) plus a new remove control that shifts the next line's values up instead of leaving the entry with no Company/Tenant/Keycard fields at all. Each additional line (`addTransferKcGroup()`) gets its own new Fee checkbox and its own ✕ that removes that line outright and renumbers the rest.
   - Server-side (`buildKeycard()`), each extra keycard line's email-body text now prints its own `(extra key, $30)` suffix when its Fee box is checked, and the AR/Novie CC-billing note now sums $30 per checked Fee box across the whole Transfer entry instead of one flat $30 regardless of how many keycards.
4. **Only one "Add Keycard" control while a request is pure-Transfer** — the top-level `+ Add another keycard` (adds a whole new Card/entry) now hides under the same `eraKeycardAllTransfer()` condition as `era_k_locationGroup`, since the in-entry `+Add Another Keycard` already covers adding more keycards under the same Transfer From/To pair(s). It reappears the instant any entry isn't Transfer.
5. `+Add Another Location` and `+Add Another Keycard` now sit side by side (new flex CSS on `.era-k-transfer-btnRow`) instead of stacking full-width.
