# 2026-08-16 — CW Email Request, Phone tab: Serves gate, four request-type checkboxes, Employee ID field

Added a `<select id="era_ph_serves">` (Cubework/Unis, mirrors Keycard's `era_k_serves`) at the top of the Phone tab; nothing else in the tab shows until it's picked (everything else moved into a new `#era_ph_body`, revealed via `eraApplyPhoneServesVisibility()`). The two existing checkboxes ("New Phone Line"/"Troubleshoot") were relabeled/extended into four mutually-exclusive ones — "New Phone" (renamed, id `era_ph_create` unchanged), "Troubleshoot", "Replacement", "Activate" — via new `ERA_PH_CHECK_IDS`/`eraApplyPhoneCheckExclusivity()`. Replacement/Activate have no fields of their own yet (no spec given) — ticking either just hides both the New Phone and Troubleshoot field groups. New Phone gained an "Employee ID" field (optional) under Person Title. Server-side, `buildPhone()` gained a Serves validation (mirroring `buildKeycard()`), a `Serves:` email line, "Replacement"/"Activate" added to the `Request:` label, an `Employee ID:` body line, and two latent-bug fixes surfaced by "neither New nor Troubleshoot ticked" becoming a normal state: the greeting line no longer defaults to claiming "troubleshoot" (new fallback: "Please process the phone request below:"), and the subject line no longer prints a literal "undefined undefined" when neither type is ticked.

Files: `public/index.html`, `functions/emailRequest.js`
