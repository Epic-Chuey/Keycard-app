# 2026-08-01 — Parser and UI fixes

Taught the heuristic Keycard parser (`functions/parseEmail.js`) to handle five real free-form email shapes (labeled fields, unlabeled inline company+cardholder+keycard lines in various orders, multi-cardholder blocks, subject-only info with a stated card-number range), adding top-level `cardholderEntries`, `access`, `serves`, `email`, `phone` fields to `extractFields()` — `email`/`phone` stayed ticket-level (not per-entry) pending a real example of that format. Added a structured summary (`buildOriginalRequestSummary()`) to the "View Original Request" modal, one line per field, flagging any keycard number shared by more than one cardholder entry in red as "(duplicate)". Fixed a `resyncKeycardAttachments`/`resyncNewHireAttachments` timeout (raised client timeout to 540s, server `timeoutSeconds` 300→540, commit every 20 docs instead of one final batch) and scoped "Fix attachments" to only the currently-rendered tickets unless the "All" filter is active.

Made the app-switcher tabs sticky by moving `#appSwitcher` out of `.app-hero` (a `position: sticky` element's range is bounded by its nearest positioned ancestor, and the hero was `position: relative`), which left the hero rendering as an empty decorative strip on some views. Also made the Keycard/Wi-Fi mode tabs inside the embedded `email-request.html` iframe stay visible while scrolling via manual cross-frame position tracking (native sticky doesn't work there since the host resizes the iframe to its full content height) — this absolute-positioned approach was later replaced (see [Known pitfalls](../pitfalls.md)).

Files: `functions/parseEmail.js`, `public/index.html`, `public/app.js`, `public/email-request.html`
