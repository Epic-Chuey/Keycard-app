# 2026-08-13: CW Email Request moved off Google Apps Script onto a standalone Cloud Function (Microsoft Graph)

CW Email Request kept failing with "Send failed: Gmail operation not allowed" even after the account migration/URL repoint, so it was moved off Apps Script/Gmail entirely. New `functions/emailRequest.js` ports the Apps Script `Code.js` (same six modes, recipients, subject/body/validation rules) but sends via Microsoft Graph's `/me/sendMail` (small attachments inline; large ones via a draft + upload-session flow) instead of `GmailApp.sendEmail()`, exposed as a new `submitEmailRequest` callable in `functions/index.js`. `graphAuth.js`/`get-refresh-token.js` needed a `Mail.Send` scope, but it's requested only via an opt-in `extraScopes` param (new `getGraphClientForSend()`, used only by `submitEmailRequest`) after an early version requested `Mail.Send` unconditionally for every Graph caller and broke Standup's Pull (which only ever had `Mail.Read` consent) once deployed. Since Azure AD `Mail.Send` wasn't actually working yet, the embed on `public/index.html` cycled through fallbacks that day — a brief link back to the old Apps Script project (rejected), then a client-side "Open in Outlook" deeplink (`eraOpenInOutlook()`, using a new build-only `buildEmailRequestPreview` callable to validate/build the email without sending) — settling on an `ERA_SUBMIT_MODE` constant (`"outlook"` vs `"graph"`) that also hides/shows the six `.era-attach-section` file pickers; while hidden, Keycard's mandatory-attachment server check is satisfied with a placeholder `{filename: "attached-by-hand-in-outlook"}` entry. Needs Azure AD `Mail.Send` added to the app registration and `MS_REFRESH_TOKEN` re-minted with that scope before Graph sending actually works; not deployed or live-tested from this session.
