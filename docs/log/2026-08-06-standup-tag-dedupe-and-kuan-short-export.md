# 2026-08-06 — Standup: duplicate-tag report bug fixed, "View Short/Long Version" added, "View Report" made fully editable

Fixed a bug where the Report step showed a tag section (e.g. "Camera") duplicated: `addStandupTag` never checked for an existing tag with the same label before inserting, so two custom tags could share a visible label under different `custom:<id>` keys, and `buildStandupSummaryDetailSectionsHtml()`/`buildStandupExcelWorkbook()` grouped strictly by raw key. Fixed going forward (`addStandupTag` and the client's "+ New tag..." handler now reuse an existing same-labeled tag id case-insensitively), and added `standupTagGroups()` to merge same-labeled keys for already-affected data — used by the report, Excel export, and `buildStandupEmailBody()` (same underlying bug, same fix).

Added "View Short Version" / "View Long Version": expand/collapse panels (not downloads, per Huy's follow-up) using Vertex AI Gemini (`gemini-2.5-flash-lite`) to produce a short broad-theme brief or a longer per-task detailed brief. `parseStandupKuanShortSummary`/generalized `parseStandupKuanBriefSummary(kind)` tolerantly parses loosely-formatted AI output into `{intro, highlights}`; results cache per `save.id` in `standupKuanBriefCache` (in-memory only, lost on reload). Both support manual editing (DOM-read-at-save-time form) and "Regenerate"; unlike `summarizeStandupEntries`'s fail-closed pattern, this throws on failure and shows an inline retry box.

Made "View Report" in the Saved step fully editable instead of showing a frozen read-only snapshot: an "Entries" editor (same row shape as the live checklist) lets past days' `save.items` be edited and re-saved via the existing `saveStandupReportFn`. A same-day follow-up extended this to "Summary for Kuan Goh" itself — confirmed with Huy that unmatched locations should still go through the "ask before adding" catalog flow, and that this view should **replace** the frozen snapshot going forward (not sit alongside it) — so "View Report" now shows three live pieces driven off `save.items`: an editable Summary editor (`buildStandupSaveSummaryEditorHtml()`, its own intro persisted via a new `summaryIntroText` field on `standupSaves/{date}`), a location-candidates prompt, and the Entries editor. Core report-generation functions (`standupIncludedItems`, `buildStandupSummaryIntroText`, `buildStandupReportHtml`, etc.) were parameterized to accept `items`/`introText`/`dateStr` instead of hardcoding live-checklist globals, so both the live Report step and the Saved-step editors share one code path.
