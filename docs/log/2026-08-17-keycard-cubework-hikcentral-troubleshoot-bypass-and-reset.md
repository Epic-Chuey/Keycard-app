# 2026-08-17: CW Email Request, Keycard tab: Cubework+HikCentral+Troubleshoot validation bypass, full-form reset after successful Submit

Two Keycard-tab changes. (1) A keycard entry set to Cubework (Serves) + HikCentral (Systems) + Troubleshoot (per-entry action) now bypasses Tenant Company Name/Tenant First-Last Name and attachment validation on Preview — scoped narrowly via `isKeycardCubeworkHikTroubleshootEntry()` in `functions/emailRequest.js` (`buildKeycard()`) and its client mirror `eraKeycardIsCubeworkHikTroubleshootOnly()` in `public/index.html`; every other combo (Unis, Cubework+Unifi, or any non-Troubleshoot action) still requires them. Subject/entry lines fall back to a "HikCentral Troubleshoot"/"HikCentral" label instead of a blank company name. (2) After a real Graph-send Submit succeeds, the whole tool now resets to a fresh blank form — new `eraResetToFreshForm()` (using `eraSetCheckedAndFire()`/`eraSetValueAndFire()` to replay real "change" events through existing visibility listeners) clears all fields/attachments/entries across every mode back to page-load defaults and returns to the Keycard tab, called right after `eraShowSuccess(res)` in `eraSubmitForm()`'s success branch. The Outlook-deeplink fallback path is not reset, since it never gets a confirmed "sent" result back.

Files: `functions/emailRequest.js`, `public/index.html`
