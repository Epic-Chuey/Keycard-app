# 2026-08-16 (tenth pass) — CW Email Request, Application/Software + Laptop: Request Type checkbox exclusivity

Extended the Printer/Phone request-type mutual-exclusivity pattern to the App and Laptop tabs' two checkboxes each ("New Install / Access"/"Troubleshoot" and "New Laptop"/"Troubleshoot") — ticking one now unticks the other. Neither tab has a Serves gate (that's Printer/Keycard/Phone-only), so only the exclusivity behavior applies. New generic helper `eraApplyCheckboxPairExclusivity(idA, idB, activeId)` wired to `era_ap_create`/`era_ap_troubleshoot` and `era_lt_create`/`era_lt_troubleshoot`. Unlike Printer/Phone's helpers, this one also fires a synthetic `change` event on the checkbox it force-unchecks, because these two tabs' Troubleshoot boxes each drive their own field-visibility listener directly (`eraBindToggle("era_ap_troubleshoot", "era_ap_issue", true)`) rather than a shared `eraApplyPrinterVisibility()`/`eraApplyPhoneModeVisibility()` recompute — without the synthetic event, force-unchecking Troubleshoot would leave the issue box stuck visible. No changes to `eraCollectFields()` or `functions/emailRequest.js` — both booleans were already independently handled; exclusivity is just a stricter subset.
