# 2026-08-02 → 2026-08-03 — Pull/Checklist/Email steps merged, retired AI model found and dropped, location auto-detection added

Collapsed Standup's 5-step workflow to 4 (see [Standup tab](../standup-tab.md)). Root-caused "summarization doesn't work" via web search rather than log access: `gemini-2.0-flash-001` (`STANDUP_AI_MODEL`) had been shut down by Google on 2026-06-01, so `summarizeStandupEntries` had been silently 404-ing and falling back to plain truncation with no visible error. Swapped to `gemini-3.5-flash` (avoiding `gemini-2.5-flash`, itself scheduled to retire 2026-10-20). Once the fallback text was visibly still just "the latest reply," the summary line was removed from `renderStandupChecklist` entirely (along with `standupEntrySummaryText`), and the `summarizeStandupEntries` call was dropped from `pullStandupEmails` too (function left in place for future reuse).

Merged the read-only "Pull" list and editable "Checklist" step into one — `renderStandupMessageList` removed, pulling now seeds `standupChecklistItems` and renders `renderStandupChecklist()` inline. Report/Email/Saved shifted from steps 3/4/5 to 2/3/4, then Email itself was folded into Report (its "Open in Outlook Web" button moved next to "Generate report"), leaving 3 steps total. Added `standupRefreshReportIfGenerated()` so Download HTML/PDF/Save/Open-in-Outlook always rebuild from current checklist state rather than a stale snapshot.

Fixed `AADSTS90015` ("query string too long") on "Open in Outlook Web": the deeplink's `body` param carried the whole report and hit Azure AD's URL length cap on longer reports. Dropped `body` from the deeplink (now only `to`/`subject`) and copy the body to clipboard instead (with `prompt()` fallback). Full write-up in [Known pitfalls](../pitfalls.md).

Added location auto-detection: `standupDetectLocationState()` fuzzy-matches ticket text against the address catalog (`public/locations.js`), requiring the street-number token plus one more overlapping word to avoid false positives; `standupBuildLocationBreakdown()` auto-seeds a Cali/Outside-Cali breakdown into the editable Report intro. A follow-up added an "ask before adding" flow (`standupLocationCandidates()`, `renderStandupLocationCandidates`) so unmatched but address-like text prompts a California/Outside-CA/Not-a-location choice, writing confirmed entries via a new `addStandupLocation` callable into a new `standupLocationCatalog` Firestore collection — the only way the catalog grows without a code deploy.
