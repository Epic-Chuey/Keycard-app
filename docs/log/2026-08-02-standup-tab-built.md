# 2026-08-02 — New Standup tab, built end-to-end

Built the fifth tab, "Standup," implementing a 5-step workflow (Pull → Checklist → Report → Email → Saved) across `public/index.html`, `public/app.js`, `functions/index.js`, `firestore.rules`. See [Standup tab](../standup-tab.md) for current architecture. Pull was rescoped from the whole mailbox to Sent Items only (`STANDUP_SOURCE_FOLDER_PATH`), plus a per-thread `conversationId` lookup (`fetchConversationRootMessage`) since a reply's own body is often just "Thanks." Checklist sorts by tag and shows a one-line summary per entry, eventually backed by real AI (`summarizeStandupEntries`) with plain-truncation as fallback. Report auto-generates a boss summary (Kuan Goh) split into an always-live colored per-tag breakdown plus a separately editable intro sentence, so edits can't clobber the colored sections; PDF export uses `html2canvas` + `jsPDF` with custom pagination since html2canvas can't honor CSS page-break rules. Email reuses Report's own summary state (`buildStandupEmailBody()`) rather than building its own. Saved is backed by a new `standupSaves/{date}` Firestore collection, write-blocked for clients, written via `saveStandupReport`; both the Report Save button and Email's "Open in Outlook Web" trigger a save.

AI summaries went through two backend pivots — Anthropic API (no key available) then Vertex AI Gemini via the Cloud Function's own GCP service account, landing on the current `@google/genai` SDK after finding `@google-cloud/vertexai` deprecated. `summarizeStandupEntries` fails closed (returns null on any error) so Pull never breaks because of it.

Files: `public/index.html`, `public/app.js`, `functions/index.js`, `firestore.rules`, `functions/package.json`
