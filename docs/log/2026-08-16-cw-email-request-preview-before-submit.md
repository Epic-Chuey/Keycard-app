# 2026-08-16 — CW Email Request: preview step before Submit, all six tabs

Every CW Email Request tab (Keycard/Wi-Fi/Printer/Phone/Application-Software/Laptop) now shows a preview before sending/opening. The shared bottom button (`#era_submitBtn`) is always labeled "Preview" and its click now calls new `eraPreviewClick()`, which runs a new shared `eraRunPreflightChecks()` (consolidates the location/requester-email-required, Keycard's attachment-required, and Printer's Tenant+Troubleshoot-attachment-required checks that used to be duplicated inline) then calls the existing `buildEmailRequestPreview` Cloud Function (`functions/index.js`, wrapping `buildEmailRequest()` in `functions/emailRequest.js` — unchanged, no server work needed since this callable already validated-and-built without sending). Results show in a new `#era_previewModal` (To/Cc/Subject as text, body via `innerHTML`, preferring `htmlBody`) with Edit/Submit buttons; `eraPendingPreviewResult` holds the shown result so Submit acts on it without re-fetching. `eraSubmitForm()` (real Graph send) and the renamed `eraOpenOutlookFromPreview(res)` (replaces `eraOpenInOutlook()`) both now consume that cached result instead of re-running the preflight/build themselves from scratch. Verified via a scripted jsdom test exercising both `ERA_SUBMIT_MODE` values end-to-end (not a live deploy).
